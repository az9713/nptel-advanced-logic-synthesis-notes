[L25 11:19](https://www.youtube.com/watch?v=RpNbQDah6MM&t=679s) · [L25 23:38](https://www.youtube.com/watch?v=RpNbQDah6MM&t=1418s) · [L25 86:49](https://www.youtube.com/watch?v=RpNbQDah6MM&t=5209s)

After clock-tree synthesis, propagation through the clock network determines clock latency per endpoint. A setup or hold worst-case analysis can assign different delay assumptions to launch and capture branches. If these branches share a physical segment, treating the shared part as independently early and late can introduce pessimism. **Common-path pessimism removal** credits the portion attributable to that incompatible treatment when the analysis assumptions permit it. For example, a shared segment analyzed as 100 ps on launch and 80 ps on capture has a 20 ps difference. If the timer determines this difference is entirely artificial for the chosen check, removing it improves reported slack by 20 ps. The correction neither accelerates the data nor removes variation from unshared branches. [L25 78:35](https://www.youtube.com/watch?v=RpNbQDah6MM&t=4715s)

## Lab 08 · Choose a fix and verify its collateral effects [L26 13:04](https://www.youtube.com/watch?v=r4j0wv_dDyw&t=784s) · [L26 32:23](https://www.youtube.com/watch?v=r4j0wv_dDyw&t=1943s)

If a path is too slow, an engineering change may reduce fanout, improve slew, move logic, or replace a cell with a stronger or faster equivalent. Increasing drive can also increase input capacitance and make the preceding arc worse. If a path is too fast, insert delay where it affects the intended endpoints. A buffer immediately before a violating capture data pin can target one endpoint more narrowly than a buffer near a shared launch point. Retest setup, hold, electrical limits, and power in the declared scenarios after each change.

In an illustrative two-corner analysis, minimum data delay must increase by 18 ps to fix hold. A buffer adds 22 ps at the min corner and 35 ps at the max corner. Hold ends with +4 ps, and a path with original +26 ps setup slack ends with −9 ps if other terms stay fixed. That intervention moves the violation from hold to setup. Look for a location or cell with a better spread, or create setup margin elsewhere.

The lecture also uses tool collections to investigate pins and cell attributes. When automating a report across macro endpoints, query their pins with direction and clock distinctions, inspect collection size, and deliberately include paths that report no timing. An empty collection has no implication about positive slack. [L26 46:23](https://www.youtube.com/watch?v=r4j0wv_dDyw&t=2783s)

In the demonstrated Tcl interfaces, an EDA collection represents tool objects. Iterate it using the collection API, such as `foreach_in_collection`, and resolve each object's reported name when writing results. Capture the pin, rise/fall transition, min/max check, and scenario with the reported slack. The same pin can need more than one row when those fields differ. ## Lab 09 · Characterize and compile block hierarchy [L27 05:51](https://www.youtube.com/watch?v=hcrQYacN3IY&t=351s) · [L27 33:16](https://www.youtube.com/watch?v=hcrQYacN3IY&t=1996s)

Bottom-up compilation allows a separately synthesized divider, counter, or arithmetic block to be reused at top level. Capture a block's environment from the parent where possible. Then apply its constraints in a stand-alone run and validate the assembled result under the original parent context. A subdesign may appear in multiple contexts. If the contexts differ, decide whether to use one conservative implementation or allow separate variants and check each.

The **characterize-and-write-script** workflow in Lab 09 starts from a timing-bearing parent build, characterizes selected instances in context, and writes each block's derived environment before the stand-alone compile. Reassemble bottom-up in dependency order. If a reloaded parent still contains generic GTECH cells in a block expected to be mapped, check the block build and the library/link order. An old elaborated definition already in memory can mask the newly compiled one. Confirm the actual references inside the assembled hierarchy. [L27 07:34](https://www.youtube.com/watch?v=hcrQYacN3IY&t=454s) · [L27 27:50](https://www.youtube.com/watch?v=hcrQYacN3IY&t=1670s)

Let $A$ be the latest arrival at a block input, $d$ the internal delay, and $R$ the latest allowed arrival at its output. All three are in picoseconds on the same clock reference. Slack is $R-(A+d)$, so the permitted delay satisfies $d\le R-A$. Suppose a selector block receives its select input 300 ps after the clock and its required output is 680 ps. It has 380 ps of internal budget. A stand-alone default of 100 ps input delay suggests 580 ps of budget. A stand-alone result with 450 ps delay meets the default with 130 ps spare and fails the parent by 70 ps. Recreate the actual interface budget, investigate the important path, recompile, and check whether the new mapped references and constraints are loaded at the parent. Preserve both the parent and block reports while debugging.
