8. Debug timing and rebuild a block through four labs

The execution slice is mapped. Its synthesis report now travels to a separate timer. A discrepancy can originate in the netlist, operating conditions, clock interpretation, or constraints. Preserve the path identity and vary one assumption at a time to find the cause.

Lab 06 · Test timing exceptions in a small design L24 00:04 · L24 30:34

A timing session needs a netlist, characterized library instances, and an explicit constraint context. Set the top, resolve references, identify all clocks and endpoints, then read a specific maximum and minimum path. With no extracted parasitics, the timer uses the interconnect model available in that scenario. Save the exact session inputs so another person can reproduce the path before making a repair.

For the slice, use a complete data-path report to verify that registers launch and capture on the expected edges. Review a minimum-delay path alongside the maximum-delay path. With a 1 ns period, a maximum delay of 0.62 ns can meet setup while a 0.03 ns minimum delay fails a 0.05 ns hold requirement. Both hold events still use the same edge if the clock period increases, so the 0.02 ns deficit persists in this example.

The lab compares case analysis, false paths, and timing-arc disabling on a selector network. To see what changes, constrain an original two-input multiplexer using a virtual reference clock and explicit input/output delays. Check that both data inputs have paths to the output under the unrestricted select. Then run a scenario with select fixed to zero and check that the unselected data input has no sensitized path under that scenario. A point-to-point false path suppresses the matching timing check while leaving the network present for other analysis. Arc disabling removes the specified timing arc more broadly. Compare propagated transitions and the remaining path set. To test a false-path declaration, first give the path a valid timing requirement and show it has a checked path. Applying the exception to an already unconstrained path supplies no evidence about its selectivity. L24 38:17 · L24 49:37

Lab 07 · Reconcile post-layout inputs and clocks L25 09:46 · L25 58:33

Read the routed netlist, timing libraries, constraints, and extracted parasitics for the intended scenario. Check the parasitic annotation and compare version identities. An extraction file whose hierarchy does not match can silently reduce useful coverage. Verify clocks, generated clocks, port delays, asynchronous relationships, and the presence of a clock on each expected sequential instance. Identify the exact reported startpoint, endpoint, clock edge, and path group.

After clock-tree synthesis, propagation through the clock network determines clock latency per endpoint. A setup or hold worst-case analysis can assign different delay assumptions to launch and capture branches. If these branches share a physical segment, treating the shared part as independently early and late can introduce pessimism. Common-path pessimism removal credits the portion attributable to that incompatible treatment when the analysis assumptions permit it. For example, a shared segment analyzed as 100 ps on launch and 80 ps on capture has a 20 ps difference. If the timer determines this difference is entirely artificial for the chosen check, removing it improves reported slack by 20 ps. The correction neither accelerates the data nor removes variation from unshared branches. L25 78:35

Lab 08 · Choose a fix and verify its collateral effects L26 13:04 · L26 32:23

If a path is too slow, an engineering change may reduce fanout, improve slew, move logic, or replace a cell with a stronger or faster equivalent. Increasing drive can also increase input capacitance and make the preceding arc worse. If a path is too fast, insert delay where it affects the intended endpoints. A buffer immediately before a violating capture data pin can target one endpoint more narrowly than a buffer near a shared launch point. Retest setup, hold, electrical limits, and power in the declared scenarios after each change.

In an illustrative two-corner analysis, minimum data delay must increase by 18 ps to fix hold. A buffer adds 22 ps at the min corner and 35 ps at the max corner. Hold ends with +4 ps, and a path with original +26 ps setup slack ends with −9 ps if other terms stay fixed. That intervention moves the violation from hold to setup. Look for a location or cell with a better spread, or create setup margin elsewhere.

The lecture also uses tool collections to investigate pins and cell attributes. When automating a report across macro endpoints, query their pins with direction and clock distinctions, inspect collection size, and deliberately include paths that report no timing. An empty collection has no implication about positive slack. L26 46:23

Lab 09 · Characterize and compile block hierarchy L27 05:51 · L27 33:16

Bottom-up compilation allows a separately synthesized divider, counter, or arithmetic block to be reused at top level. Capture a block's environment from the parent where possible. Then apply its constraints in a stand-alone run and validate the assembled result under the original parent context. A subdesign may appear in multiple contexts. If the contexts differ, decide whether to use one conservative implementation or allow separate variants and check each.

Let \(A\) be the latest arrival at a block input, \(d\) the internal delay, and \(R\) the latest allowed arrival at its output. All three are in picoseconds on the same clock reference. Slack is \(R-(A+d)\), so the permitted delay satisfies \(d\le R-A\). Suppose a selector block receives its select input 300 ps after the clock and its required output is 680 ps. It has 380 ps of internal budget. A stand-alone default of 100 ps input delay suggests 580 ps of budget. A stand-alone result with 450 ps delay meets the default with 130 ps spare and fails the parent by 70 ps. Recreate the actual interface budget, investigate the important path, recompile, and check whether the new mapped references and constraints are loaded at the parent. Preserve both the parent and block reports while debugging.
